# QueQiao（鹊桥）规格设计

本文是 Rust 版桥接的**规格基线**：定义系统分层、模块职责、关键机制语义与验收方式。语义冲突时以本文为准；本文与 Node 版（qq-bridge）行为不一致处，**以 Node 版 43 个 audit 脚本钉住的契约为准并回改本文**。

## 一、定位与目标

**做什么**：把 QQ 群/私聊消息经 SnowLuma（OneBot v11）接入 DSH agent，AI 以仿真群友形态自主参与对话（看消息、发言、等待、唤醒调度、潜水、写日记）；管理端提供控制台与看门狗。

**非目标**：不重写 SnowLuma（其专有组件不进本仓库，运行时依赖官方发行包）；不做多租户/云端形态（单机单用户自托管）；不支持 DSH 之外的其他 harness（协议层不抽象通用化）。

## 二、总体架构与分层铁律

```
            ┌─ SnowLuma 官方发行包（WS 3001 / HTTP 3000）─┐
            │                                              │
queqiao-onebot（事件流+调用）      queqiao-dsh（RPC+mux 事件流）
            │                                              │
            ▼                    ▼                         ▼
      ┌───────────────────── queqiao（bin：tokio 编排）─────────────────────┐
      │  定时器 / 网络 / 文件 IO / 进程管理：全部 IO 住这一层                  │
      │  状态机驱动：事件 + now_ms → queqiao-core 决策 → 动作执行              │
      │  控制台 HTTP（axum）· 看门狗 · 配置加载与热更                          │
      └──────────────────────────────┬──────────────────────────────────────┘
                                     ▼
                     queqiao-core（纯决策，零 IO）· queqiao-media
```

**分层铁律**（Node 版踩坑结晶，Rust 版编译期+评审双重强制）：

1. `queqiao-core` 零 IO：不碰时钟（时间以 `now_ms: u64` 注入）、不碰随机（随机源以闭包/trait 注入）、不碰网络与文件；
2. 状态机采用「状态 + 事件 → 动作」纯函数形态（Elm/RRDI 风格）：副作用全部收敛为 bin 层解释执行的 `Action` 枚举；
3. 所有从 Node 版迁移的决策函数**测试先行**：Node 版对应单测逐条转译为 `#[test]`，命名与断言语义一一对应；
4. 协议层（onebot/dsh）的每个信封/事件形状都要有反序列化单测钉住，禁止 `serde_json::Value` 裸奔穿透到 core。

## 三、crate 规格

### 3.1 queqiao-core（纯逻辑内核）

| 模块 | 职责 | 迁移来源（Node 版） |
| --- | --- | --- |
| `wake` | 唤醒防卡死：回合租约常量、暂存唤醒兜底决策（Noop/Retry/Refire） | `src/wake-guards.js`（已入库） |
| `retry` | agent 回合瞬时错误分类：容量类（退避 8s/20s 重投，上限 2 次）、历史超限类（走会话压缩）、其余不重试；超时类永不重试 | `src/agent-retry.js` |
| `diary` | 日记触发三路径判定（定点 hour / 安静提前 notBefore+quietMs / 启动补写昨天）、当前日记日归属（凌晨 0~4 点归前一天）、按日去重 | `src/diary-lib.js` |
| `rate` | 唤醒/发送频率窗口判定；**失败回合退配额**语义（error 回合回滚对应 wake 计数） | bridge.js 相关段 |
| `schedule` | 唤醒优先级合并（private>at>question>…>proactiveCheck>diary）、8s 合批窗口、主动检查 30~90min 随机间隔、noAction 连续计数与配置重置 | bridge.js 调度段 |
| `media_cache` | 取图短缓存 LRU+TTL 决策 | `src/media-cache.js` |
| `search` | 多引擎解析（Bing RSS/HTML、360 网页/图片、DDG）与聚合排序（归一化去重、双源命中置顶）、引擎熔断状态机 | `src/web-search-agg.js` |
| `state` | 会话状态模型：消息/未读/唤醒配置/记忆条目/黑话条目的类型与纯变换（追加、截断、水位推进） | socialV2 状态形状 |

**决策函数签名范式**：`fn decide(state: &State, event: Event, now_ms: u64) -> Vec<Action>`；`Action` 枚举由 bin 层解释（SendPrompt / ScheduleTimer / AppendMessage / ClearTurnLease / ...）。

### 3.2 queqiao-onebot（OneBot v11 客户端）

- **事件流**（WS，默认 3001）：tokio-tungstenite；自动重连；事件反序列化为强类型 `OneBotEvent`（群/私聊消息、拍一拍、心跳——心跳的 `status.good` 是 SnowLuma hook 健康的权威信号，断流误诊教训见 Node 版注释）；
- **HTTP 调用**（默认 3000）：发送（含 reply/at 段构造）、`get_image` / `get_record` / `get_video`、表情库（`fetch_custom_face` 系）、`get_status`；
- **token 自愈**：HTTP 与 WS 是**两个不同 token**；发现逻辑读 SnowLuma home 的 per-account 配置（`snowluma-conn.js` 语义）；
- **安全**：`file` 字段只接受简单缓存文件名（防路径穿越/SSRF），本地文件读取限定在 SnowLuma home 下。

### 3.3 queqiao-dsh（DSH 私有协议）

| 子系统 | 规格 |
| --- | --- |
| Cookie 铸造 | 读 `~/.dsh/.credentials.yaml` 的 browser-session 密钥（32 字节），HMAC-SHA256 按 authority 签名自铸 Cookie；密钥缺失回退启动 token 交换 |
| 斜杠 RPC | `/api/<ns>/<method>` 信封 `{type: client-request, rpcId, method, payload:{args}}`；必备方法：session/prompt（mode=queue）、session/selectModel、session/modelCatalog、session/retire、agentPresets/list |
| mux 事件流 | `/api/remote.mux`：turn/start、tool/call、tool/result、turn/end 帧驱动状态机；**断连清理**回合状态与租约（防重复累加） |
| 端口自适应 | 探活失败时扫进程监听端口，逐候选发 modelCatalog 验证业务口（Electron 杂端口 401/404 不误判），变更写回配置（`dsh-port-sync.js` 语义） |

### 3.4 queqiao-media（后期）

图片压缩降级（超限图压进 4MB/64MP，防像素炸弹解码上限）、语音 ASR（sherpa-rs + paraformer-zh，SILK/AMR/MP3 三路解码）、视频抽帧（ffmpeg MJPEG 管道 + SOI/EOI 切分，前 90s 每 10s 一帧）。

### 3.5 queqiao（bin：编排）

- 配置加载与合并默认（config.json 兼容 Node 版形状，字段语义一致）；
- 状态机主循环：onebot/dsh 事件 → core 决策 → 动作执行；
- 控制台 HTTP（axum）：状态/会话/活动/黑话/花费面板，令牌鉴权；
- 看门狗：三组件探活（桥 HTTP 任意响应判活、DSH 端口两级探测+自发现、SnowLuma get_status）、防抖告警走 OneBot 直发私聊、重启风暴控制。

## 四、关键机制语义（迁移红线）

以下语义在 Node 版均为实战修复，规格必须原样保留（详见 Node 版提交历史）：

1. **busy 四条件**：待发送定时器、唤醒租约、投递队列、回合状态（collector/开始时间）任一为真即繁忙；消息只进暂存；
2. **回合状态租约**：任意帧刷新心跳，静默 30min 强制解除 busy；**暂存兜底** 35min 后强制补发最早一条（> 租约，保证租约先解 busy）；
3. **失败回合退配额**：error 回合回滚对应 wake 计数（防错误循环锁死频率）；
4. **历史超限自愈**：413 `chat_history_too_large` → 退役重建 DSH 会话（桥侧记忆全保留、token 轮换、重新 bootstrap）→ 3s 后重投原唤醒；10min 冷却；
5. **瞬时错误重投**：容量/限流/502/503 类退避 8s/20s 重投（重投重建 prompt 吃到新消息）；**超时类永不重投**（可能已部分执行）；
6. **日记三路径**：定点（hour，默认 23）/ 安静提前（≥notBefore 且安静 ≥quietMs）/ 启动补写昨天（10min 后检查，日期锁定为昨天、模型不可指定）；
7. **DSH 换端口自愈**（见 3.3）。

## 五、数据模型（持久化，state/ 目录，兼容 Node 版文件形状）

| 文件 | 内容 |
| --- | --- |
| `sessions.json` | key（group:/private: id）→ DSH sessionId 映射与策略元数据 |
| `social-v2.json` | 每会话：唤醒配置、recent/unread 消息、记忆、黑话锚点、频率时间戳（**白名单式序列化**：定时器/运行时字段绝不落盘） |
| `diary.jsonl` | 统一日记（date/content/key/createdAt，按日去重） |
| `stickers.json` / `slang.json` / `token-usage.jsonl` | 表情库 / 黑话 / 花费记账（形状同 Node 版） |

## 六、安全边界（Security Base 迁移清单）

1. OneBot `file` 字段白名单校验 + 本地路径限定 SnowLuma home；
2. 出站 HTTP 走受限传输（SSRF 防线：禁私网/环回/CGNAT/NAT64，DNS 全量校验，逐跳重定向复检，限量读取）——Rust 侧自实现（reqwest 不带自动重定向）；
3. 发送目标白名单（allow.groups/private）+ 模式门禁（chat/closed-agent/reserved/reserved2）；
4. 控制台令牌 + Host 校验；agent token 与控制台 token 权限隔离；
5. 敏感信息审计拦截（路径/凭据正则）回复出口。

## 七、测试与验收

1. **契约单测**：core 每模块的 Node 版单测逐条转译（断言语义一致，命名可溯源）；
2. **协议形状测试**：onebot/dsh 用真实报文样例钉反序列化；
3. **对拍验收**（最终里程碑）：与 Node 版并行接入同一测试群，同一消息序列下比对「唤醒时机/发言内容决策路径/状态变迁」；关键机制（第四节 1~7）逐项演练对拍；
4. CI：GitHub Actions（公开后启用）`cargo fmt --check && cargo clippy -- -D warnings && cargo test`。
