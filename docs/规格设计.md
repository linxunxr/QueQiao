## 一、定位与目标

**做什么**：把 QQ 群/私聊消息经 SnowLuma（OneBot v11）接入 DSH agent，AI 以仿真群友形态自主参与对话（看消息、发言、等待、唤醒调度、潜水、写日记）；管理端提供控制台与看门狗。

**非目标**：不重写 SnowLuma（其专有组件不进本仓库，运行时依赖官方发行包）；不做多租户/云端形态（单机单用户自托管）；不支持 DSH 之外的其他 harness（协议层不抽象通用化）。

## 二、总体架构与分层铁律

```
            ┌─ SnowLuma 官方发行包（WS 3001 / HTTP 3000）─┐
            │                                              │
queqiao-onebot（事件流+调用）      queqiao-dsh（RPC+mux 事件流）
            │                                              │
            ▼                    ▼                         ▼
      ┌───────────────────── queqiao（bin：tokio 编排）─────────────────────┐
      │  定时器 / 网络 / 文件 IO / 进程管理：全部 IO 住这一层                  │
      │  状态机驱动：事件 + now_ms → queqiao-core 决策 → 动作执行              │
      │  控制台 HTTP（axum）· 看门狗 · 配置加载与热更                          │
      └──────────────────────────────┬──────────────────────────────────────┘
                                     ▼
                     queqiao-core（纯决策，零 IO）· queqiao-media
```

**分层铁律**（Node 版踩坑结晶，Rust 版编译期+评审双重强制）：

1. `queqiao-core` 零 IO：不碰时钟（时间以 `now_ms: u64` 注入）、不碰随机（随机源以闭包/trait 注入）、不碰网络与文件；
2. 状态机采用「状态 + 事件 → 动作」纯函数形态（Elm/RRDI 风格）：副作用全部收敛为 bin 层解释执行的 `Action` 枚举；
3. 所有从 Node 版迁移的决策函数**测试先行**：Node 版对应单测逐条转译为 `#[test]`，命名与断言语义一一对应；
4. 协议层（onebot/dsh）的每个信封/事件形状都要有反序列化单测钉住，禁止 `serde_json::Value` 裸奔穿透到 core。

## 三、crate 规格

### 3.1 queqiao-core（纯逻辑内核）

| 模块 | 职责 | 迁移来源（Node 版） | 状态 |
| --- | --- | --- | --- |
| `wake` | 唤醒防卡死：回合租约常量、暂存唤醒兜底决策（Noop/Retry/Refire） | `src/wake-guards.js` | 已入库 |
| `retry` | agent 回合瞬时错误分类：容量类（退避 8s/20s 重投，上限 2 次）、历史超限类（走会话压缩）、其余不重试；超时类永不重试 | `src/agent-retry.js` | 已入库 |
| `diary` | 日记触发三路径判定（定点 hour / 安静提前 notBefore+quietMs / 启动补写昨天）、当前日记日归属（凌晨 0~4 点归前一天）、按日去重 | `src/diary-lib.js` | 已入库 |
| `rate` | 唤醒/发送频率窗口判定；**失败回合退配额**语义（error 回合回滚对应 wake 计数） | bridge.js 相关段 | 已入库（M4 提取） |

| `media_cache` | 取图短缓存 LRU+TTL 决策 | `src/media-cache.js` | 已入库 |
| `search` | 多引擎解析（Bing RSS/HTML、360 网页/图片、DDG）与聚合排序（归一化去重、双源命中置顶）、引擎熔断状态机 | `src/web-search-agg.js` | 已入库 |

| `v2_wait`（规格外补充） | 「话说一半」判定（qq_wait_for_messages 沉睡前观察语义） | `src/v2-wait.js` | 已入库 |

² Node 版 `src/core/session-router.mjs`（623 行 + 353 行独立测试）是每会话策略路由的实体化——模式准入/owner 边界/preset 归属/fail-closed 校验齐备，属 state 模块核心，已随 `core::session_router` 入库（31 条契约测试）；消息/未读/记忆等会话数据形状的纯变换部分仍待后续批次。

**决策函数签名范式**：`fn decide(state: &State, event: Event, now_ms: u64) -> Vec<Action>`；`Action` 枚举由 bin 层解释（SendPrompt / ScheduleTimer / AppendMessage / ClearTurnLease / ...）。

### 3.2 queqiao-onebot（OneBot v11 客户端）

- **事件流**（WS，默认 3001）：tokio-tungstenite；自动重连；事件反序列化为强类型 `OneBotEvent`（群/私聊消息、拍一拍、心跳——心跳的 `status.good` 是 SnowLuma hook 健康的权威信号，断流误诊教训见 Node 版注释）；
- **HTTP 调用**（默认 3000）：发送（含 reply/at 段构造）、`get_image` / `get_record` / `get_video`、表情库（`fetch_custom_face` 系）、`get_status`；
- **token 自愈**：HTTP 与 WS 是**两个不同 token**；发现逻辑读 SnowLuma home 的 per-account 配置（`snowluma-conn.js` 语义）；
- **安全**：`file` 字段只接受简单缓存文件名（防路径穿越/SSRF），本地文件读取限定在 SnowLuma home 下。

### 3.3 queqiao-dsh（DSH 私有协议）

| 子系统 | 规格 |
| --- | --- |
| Cookie 铸造 | 读 `~/.dsh/.credentials.yaml` 的 browser-session 密钥（32 字节），HMAC-SHA256 按 authority 签名自铸 Cookie；密钥缺失回退启动 token 交换 |
| 斜杠 RPC | `/api/<ns>/<method>` 信封 `{type: client-request, rpcId, method, payload:{args}}`；必备方法：session/prompt（mode=queue）、session/selectModel、session/modelCatalog、session/retire、agentPresets/list |
| mux 事件流 | `/api/remote.mux`：turn/start、tool/call、tool/result、turn/end 帧驱动状态机；**断连清理**回合状态与租约（防重复累加） |
| 端口自适应 | 探活失败时扫进程监听端口，逐候选发 modelCatalog 验证业务口（Electron 杂端口 401/404 不误判），变更写回配置（`dsh-port-sync.js` 语义） |

### 3.4 queqiao-media

**语音 ASR 已落地**（v0.4.19 全链，默认开启）：record 段解析 + `[语音]` 占位入库（纯语音消息不再空文本）+ 异步转写（不阻塞收消息，AI 唤醒可能先于转写完成）+ 按 message_id 回填 recent/unread（200 字截断）。引擎：**sherpa-onnx 2.0.1 官方 Rust API**（静态链 onnxruntime 单 exe 无 DLL）+ **paraformer-zh int8**（~217MB 不入包，设置页一键下载 hf-mirror 直链）+ vendor Skype SILK C 源 FFI 与 WAV 解码；16MB/180s 限额、识别串行闸（CPU 密集排队）、缺模型自动降级回占位不报错。未做：图片压缩降级、视频抽帧（ffmpeg MJPEG 管道方案保留为方向）。

### 3.5 queqiao（bin：编排）

- 配置加载与合并默认（见「十、配置规格」：config.json 兼容 Node 版形状，字段语义一致）；
- 状态机主循环：onebot/dsh 事件 → core 决策 → 动作执行；
- 控制台 HTTP（axum）：状态/会话/活动/黑话/花费面板，令牌鉴权；
- 看门狗：三组件探活（桥 HTTP 任意响应判活、DSH 端口两级探测+自发现、SnowLuma get_status）、防抖告警走 OneBot 直发私聊、重启风暴控制；
- **MCP 工具 API 宿主**：`/api/socialV2/*` 等端点为工具进程（3.6）的调用面，全部端点做「模式门禁 → agent token → 会话准入 → 工具开关 → 频率/静默 → 业务校验」六层链。

### 3.6 queqiao-mcp（MCP 工具面，独立 bin）

**架构**：DSH 按配置 spawn 的 **stdio MCP server 独立进程**（与主进程分离，Node 版同构），工具回调转译为对桥 HTTP（默认 127.0.0.1:3100）的调用。这样工具进程崩溃不拖垮主桥，且鉴权与业务校验全部收口在桥端单点。

**三层权限体系**（Node 版实战教训：漏一层就是「白烧 token + 诱导误调」或越权）：

| 层 | 时机 | 内容 |
| --- | --- | --- |
| 注册期过滤 | server 启动 | `socialV2.tools.<flag> === false` 的工具**不注册**（描述与 schema 都不给模型看，省 token 且防误调） |

## 四、运行模式与范围声明

模式体系（语义同 Node 版 RULES.md 与 `src/core/session-router.mjs`）：

| 模式 | 会话准入 | 行为 |
| --- | --- | --- |
| `chat` | 白名单群+私聊 | agent 回复自动转发、图片自动内联（一代基础形态） |
| `closed-agent` | 仅 owner 私聊 | 完整工具面（QQ 远程操控 DSH），其余通道全关 |
| `reserved`（一代仿真） | 暂同 chat | 观望/活跃/试探/退场状态机 + 规则引擎管何时说 |
| `reserved2`（二代仿真） | 暂同 chat | **本规格主体**：一切皆工具，文本不自动转发 |
| `simulation` | 同 `reserved2` | `reserved2` 的 **canonical 改名**（Node 版 QSH 计划引入）：对外查询一律给 canonical 拼写，旧名只存在于存储与迁移层 |

**每会话策略路由**（已随 `core::session_router` 入库，M1 迁移自 Node 版 session-router.mjs）：模式不再是进程级全局——每个会话可有独立 override（模式/preset/model/effort），`closed-agent` 只能来自显式 owner 条目、永不做全局默认（fail-closed 全链校验见模块文档）；preset 归属按模式校验（`simulation`→qsh-sim/qsh-sim-v2/qq-chat-v2，`closed-agent`→qsh-closed），变更返回带 before/after 的审计事件由调用方持久化。

**范围声明（M1~M5 只实现 `reserved2`（`simulation`）与其依赖的 `closed-agent` 准入语义**——owner 私聊工具透传）；`chat` 与 `reserved`（一代状态机）列入 backlog，M5 对拍切换后再评估是否迁移（当前生产仅用 reserved2，一代为遗留形态）。模式切换的**会话策略重算**（reconcile：模式变化即退役旧会话、轮换 agent token、清运行时缓存——但 preset 清单未知时跳过判定防「一次抖动全体失忆」，Node 版实战教训）属 M4 范围。

## 五、关键机制语义（迁移红线）

以下语义在 Node 版均为实战修复，规格必须原样保留（详见 Node 版提交历史）。关键机制 1~7 同时是对拍验收的演练清单：

1. **busy 四条件**：待发送定时器、唤醒租约、投递队列、回合状态（collector/开始时间）任一为真即繁忙；消息只进暂存；
2. **回合状态租约**：任意帧刷新心跳，静默 30min 强制解除 busy；**暂存兜底** 35min 后强制补发最早一条（> 租约，保证租约先解 busy）；
3. **失败回合退配额**：error 回合回滚对应 wake 计数（防错误循环锁死频率）；
4. **历史超限自愈**：413 `chat_history_too_large` → 退役重建 DSH 会话（桥侧记忆全保留、token 轮换、重新 bootstrap）→ 3s 后重投原唤醒；10min 冷却；
5. **瞬时错误重投**：容量/限流/502/503 类退避 8s/20s 重投（重投重建 prompt 吃到新消息）；**超时类永不重投**（可能已部分执行）；
6. **日记三路径**：定点（hour，默认 23）/ 安静提前（≥notBefore 且安静 ≥quietMs）/ 启动补写昨天（10min 后检查，日期锁定为昨天、模型不可指定）；
7. **DSH 换端口自愈**（见 3.3）。

## 七、安全边界（Security Base 迁移清单）

1. OneBot `file` 字段白名单校验 + 本地路径限定 SnowLuma home；

5. 敏感信息审计拦截（路径/凭据正则）回复出口。

## 十二、主动智能与自进化增强（借官方 Super-agent 设计，M5 后增量）

**P3 立项要点（记忆二期与周期复盘，2026-11-01）**——治理面（版本化/审批流）已齐，本批补学习面：

- **周期复盘**：复用 proactiveCheck 的调度形态，每 N 天（默认 7）安静时段触发「复盘回合」——agent 审视近期记忆/日记/人格的一致性，产出仅为**提议**：记忆精修（qq_memory_append/remove 直改自己的记忆域）、黑话提议（qq_slang_submit）、人格卡提议（qq_propose_role_edit）——人格/黑话仍走 owner 审批门控；复盘本身只读+提议，无直接改写路径。
- **长期记忆**：记忆条目升级带 retention 分层（短期 episodic → 蒸馏 distilled 长期层），跨月沉淀；检索层（按需语义检索）落地时**一并迁 SQLite+sqlite-vec**（触发信号：长期化 / P2 多会话并发写 / 跨会话共享记忆，任一出现即迁；此前维持 JSON 的用户可读可改特性——单用户当前量级下换库收益为零，不为对齐官方形态而迁）。
- **红线延续**：复盘产出的自修订全部过 owner 门控；长期记忆进上下文仍走「索引注入+查询详情」分层（token 经济不因记忆扩容回退）。

**两条红线**（照搬官方会翻车）：

1. 注意力经济重定义——鹊桥价值函数是"仿真度 × 话题相关性 ÷ 冷却惩罚"，门禁目标是群友舒适区而非最小化发言（真人群友会说废话，人格魅力是产品目标的一部分）；参数实测调，不从原型搬。
2. 自修订 mandate 收紧到 owner——QQ 群开放环境，agent 自改 prompt 权限若对群友开放等于人格可被诱导劫持；仅 ownerQQ（closed-agent 会话）可批准生效，每次修订记录准入途径（官方 MandateBasis 的鹊桥版）。
